# Launch

Launch's marketing and documentation website, built from `nckrtl/launch-starter-kit`.
The reusable kit lives in that separate repository; do not treat this application as its checkout.

  project rules and safety boundaries override generic package examples.
- Use version-specific Boost `search-docs` (or the harness `search_docs`) before
  applying uncertain framework APIs. Inspect sibling code first; follow existing conventions.
- MCP setup and refresh instructions: [.ai/README.md](.ai/README.md).
  Never replace Orbit-injected MCP settings or commit credentials / `.env` files.

## Commands (source of truth: composer.json / package.json)

| Command                             | Purpose                                                                        |
| ----------------------------------- | ------------------------------------------------------------------------------ |
| `composer install`; `bun install`   | Install locked dependencies; Bun also installs VitePlus hooks                  |
| `bun run build`                     | Client **and SSR** production builds                                           |
| `vp build`                          | Client-only build; not SSR verification                                        |
| `vp check` / `vp check --fix`       | Oxc lint/format checks / fixes                                                 |
| `composer test`                     | Unit + Feature via `scripts/run-pest.php`; full before first commit, TIA after |
| `composer test:browser`             | Build assets, own SSR process, run `tests/Browser`, stop owned process         |
| `composer analyse`                  | PHPStan / Larastan level 9                                                     |
| `composer lint` / `composer rector` | Pint formatting / Rector upgrades (mutating)                                   |
| `composer check`                    | Canonical validation gate; inspect current script for its exact checks         |
| `composer fix`                      | Rector + Pint + VitePlus fixes                                                 |

Chromium is a separate prerequisite: `bunx playwright install chromium`.
`composer test` does **not** run Browser tests. Direct `vendor/bin/pest tests/Browser`
requires existing built assets and an appropriately owned SSR service; prefer the runner.

## Environment and safety

- Read `README.md` for this application's environment. The guides in
  `resources/markdown/environments/` describe Launch users' environments, not an
  authorization to start or modify this task's infrastructure.
- Under Orbit or Herd, never start `composer dev` / `php artisan serve` over a managed
  app. `vp dev` is Vite-only; run it only when the environment authorizes that process.
  `composer dev` is for an unmanaged local environment with no existing service.
- Orbit workspaces start without a topology. Request one through a blocked reviewer
  consult if discovery needs it; never acquire/release one yourself. Operate only on
  allocated disposable fixtures, not live/shared resources or another task's fixtures.
- In Orbit, do not fetch or push; Orbit fetches and publishes. Follow the task's handoff
  command and evidence requirements. Do not change shared host permissions to unblock checks.
- Preserve the VitePlus dispatcher and committed `.vite-hooks/`; `vp config` installs
  it via Bun's prepare script. Pre-commit runs `vp staged`. One-shot bypass:
  `VP_GIT_HOOKS=0`. Do not configure `hook.*` Git keys (nothing reads them).

## Completion gates

Every feature needs automated coverage: focused PHP tests for backend behavior,
Inertia component/prop assertions for page responses, and Pest Browser tests for
user-visible workflows. UI changes also require manual real-browser verification,
including console errors, using agent-browser or equivalent.

Run `composer check` before handoff. Report exact tests and browser validation that
passed; if browser validation is skipped, explicitly explain why there is no
user-visible UI surface. Feature tests disable Vite/SSR deliberately: do not re-enable
SSR to fix them or claim they prove SSR coverage. Preserve the browser runner's stronger gate.
